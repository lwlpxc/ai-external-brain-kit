# RAG（检索增强生成）

RAG = 切片 + 向量检索 + 召回 + 重排 + 生成。原理简单，落地难——**解析和清洗占六成工作量**。企业动机：私有信息通用大模型没学过；信息量大容易突破上下文限制。

## 流水线

1. **切片**（提问前的准备）：固定切片（token 固定，简单）、递归切片（按段落限长）、结构切片（按章节标题）、语义切片（主题变了才切）、父子切片（子块检索、父块回答，适合产品手册）、Agent 切片（agent 规划，复杂文档）
2. **向量化**：多维向量保存数据，角度/距离越近关系越大
3. **召回（海选）**：问题转向量比角度，按 top-k 和阈值取；只判断语义相似，不代表能正确回答
4. **重排（复试）**：问题与候选拼接给 rerank 模型算注意力，分高者胜
5. **生成**：用户问题 + 重排后资料 + 约束指令一起给模型

## 落地难点

- **解析**：模型只要 md/txt，需把 PDF 等转换并保留排版、表格、标题结构
- **清洗**：降噪清洗（页脚/空行/错符）+ 业务清洗（版权号、型号留不留由用户定）
- **权限**：用元数据做权限控制
- **混合检索**：语义检索（相似度）+ 关键词检索（字面命中）
- **提问模糊**：交互澄清（反问）或联系上下文问题改写
- **多文档提取答案难**：图谱 RAG（成本高）/ Agent RAG（agent 拆解问题，有幻觉）

## 优劣

优势：成本低、知识迭代快、问题可追溯、数据安全。弊端：依赖文档、向量检索不够严谨、多文档提答难。
