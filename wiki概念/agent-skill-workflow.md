# Agent 与 Skill 工作流

用 AI（Agent + Skills）协作开发嵌入式项目的个人方法论，聚合自《如何让 AI 与嵌入式结合》心得与 skill 方法论笔记。源自 2026-10-19 的笔记摄取。

## 基本分工

- **Agent 是调度者**：理解意图 → 收集信息（门禁，如芯片型号、demo 路径）→ 路由给对应 Skill。解决的是**调度问题**，不是执行精度问题。
- **Skill 是技能包**：把一条重复工作流沉淀成 AI 可复用的确定性流程，解决执行精度问题。

## Skill 的两种生成方式

1. **跑通蒸馏法**：先人工协作把事跑通一次，再让 AI 把过程蒸馏成 Skill。适合"已经做过、有成功样本"的工作流，自带真实路径与真实坑。
2. **逆向工程法**：把模糊想法告诉 AI，让 AI 反向提问，需求自动理清。适合"想做但没做过"的东西。

蒸馏前加一轮**分辨式提问**（来自 [[AI学习]] 的 skill 模板）：① 哪些操作所有页面共通、哪些是该页面特有？② 哪些坑是流程自带、哪些是侥幸没踩到？③ 做过哪些没写进对话的默会判断？

## 配套机制

- **框架立边界**：嵌入式六层（硬件层 → HAL → Core → BSP → 中间件 → App）要落成 AI 能读、脚本能查的规则（AGENTS.md / lint），AI 才是在"填空"而不是"作文"。
- **盲点补偿**：逻辑盲点让 AI 反驳；感知盲点（实机、原理图、波形）靠喂同一份素材（截图、手册原文、叠图比对）。
- **验证回路（由弱到强）**：人肉抽查 < AI 看图比对 < 确定性脚本 < 实机运行。编译通过是最弱的门禁，终点必须落到实机行为；回路要脚本化、秒级，才跑得勤。
- **迭代纪律**：最小可运行案例先行，跑通即存黄金范例模板；每次返工回写一条坑记录（症状/原因/办法）。
- **节奏**：单个 Skill 先打磨成确定性流水线，攒到四五个再写薄的编排 Agent。

## 全链路

框架立边界 → Skill 沉淀经验（蒸馏/逆向）→ 反驳 + 喂料补盲点 → 强回路验证 → 坑回写迭代 → Skill 攒够再上 Agent 编排
