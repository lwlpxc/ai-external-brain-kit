# 摘要：《如何让 AI 与嵌入式结合》学习计划与心得

一篇课程学习 + 实战复盘的方法论文章。核心主线：**框架立边界 → Skill 沉淀经验 → 闭环验证 → 坑回写迭代**。

## 学习计划脉络

- 第 1 周（工具与概念）：Claude Code + cc-switch + Deepseek 环境链路；Agent = 调度者、Skill = 技能包；嵌入式六层框架（硬件层 → HAL → Core → BSP → 中间件 → App）
- 第 2 周（工作流与知识库）：编排型 Agent（只做理解意图 + 收集信息 + 路由）+ 两个 Skill（芯片最小可编译工程生成、Datasheet → 驱动代码生成）；Obsidian 知识库
- 长期：把项目中重复率最高的"新页面开发"流程蒸馏成 Skill，持续踩坑回写

## 六条核心心得

1. **分层的本质是给 AI 画填空格**：层分得越清楚，指令越精准、幻觉越易定位、换芯片只动 HAL/Core。前提是分层要落成 AI 能读、脚本能查的规则（AGENTS.md / 导览文档 / lint），否则 AI 做的还是作文。
2. **Skill 的两种生成方式**：跑通蒸馏法（做过、有成功样本，实证性强）vs 逆向工程法（想做但模糊，让 AI 反向提问理清需求）。蒸馏前加一轮"分辨式提问"：区分共通/特有操作、流程自带的坑/侥幸没踩的坑、没写进对话的默会判断。（该提问模板的最早单独记录见 [[AI学习]] 中 skill 条目）
3. **盲点分两种**：逻辑盲点靠让 AI 反驳；感知盲点（实机、原理图、波形）AI 天生看不见，只能喂同一份素材（截图、手册原文、叠图比对）。"对图回修"有效是因为走感知闭环而非讨论闭环。
4. **回路的强弱排序**：人肉抽查 < AI 看图比对 < 确定性脚本 < 实机运行。推论：编译通过是嵌入式里最弱的门禁，回路终点必须落到实机行为；回路要便宜（脚本化、秒级）才跑得勤。
5. **别急着上多 Skill 的 Agent**：Agent 解决调度问题不是执行精度问题。先把单个 Skill 打磨成确定性流水线，攒到四五个再写薄的编排 Agent。
6. **最小案例 + 黄金范例 + 坑回写**：先生成最小可运行案例再开枝散叶；跑通后存成模板照抄起步；每次返工必须回写一条坑记录（症状/原因/办法）再收工——蒸馏只是 Skill 的出生，坑回写才是成长。

## 方法论全链路

> 框架立边界 → Skill 沉淀经验（蒸馏/逆向）→ 反驳 + 喂料补盲点 → 强回路验证 → 坑回写迭代 → Skill 攒够再上 Agent 编排

AI 工具会过时，"怎么和 AI 协作"的方法论是跟项目走的长期资产。

【易错：编译通过 ≠ 能跑，门禁必须落到实机行为；分层不落成可查规则就只是脑内规范，对 AI 无约束力】
