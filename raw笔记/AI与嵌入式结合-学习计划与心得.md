# 《如何让 AI 与嵌入式结合》学习计划与心得

> 一名嵌入式工程师的 AI 工作流入门实录：从装好 AI 搭档，到用 Agent + Skills 把重复劳动交给 AI，再到踩出属于自己的一套方法论。课程教的是"怎么用工具"，真正让我开窍的是后面自己悟出来的东西。

---

# 学习目标：

- 配好 Claude Code + Deepseek 开发环境，建立对 Agent / Skill 的正确认知
- 用"先跑通、再蒸馏"的方法，把工作中最重复的一项任务沉淀成自己的 Skill
- 建立个人嵌入式 AI 工作流方法论：**框架立边界 → Skill 沉淀经验 → 闭环验证 → 坑回写迭代**

---

# 学习内容：

**第 1 周：工具与概念**

1. 第一节 装好 AI 搭档：Claude Code + cc-switch + Deepseek V4 Pro（1M 上下文）；Git / Node / Terminal 环境链路
2. 第二节 Agent 和 Skills：Agent 是调度者、Skill 是技能包；用 @Agent 统一调度优于 /skill 单独调用；"逆向工程"提问法理清需求
3. 第三节 嵌入式框架体系：硬件层 → HAL → Core（片上外设 + 内核基础设施）→ BSP（片外外设）→ 中间件（RTOS / LVGL）→ 应用层

**第 2 周：工作流与知识库**

4. 第四节 搭建 Agent 工作流：编排型 Agent（不蛮干，只做理解意图 + 收集信息 + 路由）+ 两个 Skill（芯片最小可编译工程生成、Datasheet → 驱动代码生成）
5. 第五节 Obsidian 管理知识库

**长期：实战深化（真正出活的地方）**

6. 把自己项目里重复率最高的"新页面开发"流程蒸馏成 Skill，并持续踩坑回写迭代

# 学习心得（比课程本身更值钱的部分）

## 1. 分层的本质：给 AI 画填空格

课程里讲嵌入式六层框架（硬件层 → HAL → Core → BSP → 中间件 → App），一开始我以为这只是代码规范，学完才反应过来：**AI 写代码就是在做填空题，而框架就是那张卷子**。层分得越清楚：

- 我给 AI 下的指令越精准（"在 BSP 层加一个按键驱动"，AI 不会乱动应用层）；
- AI 的幻觉越容易被在正确的层级里定位和修正；
- 换芯片时 AI 只改 HAL 和 Core，BSP 小改，App 一行不动。

但有个前提很容易被忽略：**分层不能只存在脑子里，要落成 AI 能读、脚本能查的规则**（AGENTS.md / 导览文档 / lint 检查）。空格的位置和边界先画出来，AI 才是填空；否则它做的还是作文。

## 2. Skill 的两种生成方式，各有各的入口

- **跑通蒸馏法**：先跟 AI 协作把一件事完整跑通一次，再让 AI 把过程蒸馏成 Skill。适合"已经做过、有成功样本"的工作流，天然带着实证（真实路径、真实坑）。
- **逆向工程法**：把模糊想法告诉 AI，让 AI 反过来向你提问，一路答下来需求自动理清。适合"想做但没做过、想法还模糊"的东西。

我偏爱第一种，因为 Skill 的质量来自实战检验而不是初次生成的方式。但"直接生成"有个病：AI 分不清通用和特例，也看不见我做过的默会判断。所以蒸馏前值得加一轮**分辨式提问**：

> 我刚跑通了一个新页面的完整流程，现在要沉淀成 Skill。先别写——逐个向我提问，帮我分辨：① 哪些操作是所有页面共通的，哪些只是这个页面特有的？② 哪些坑是流程自带的，哪些是这次运气好没踩到的？③ 我做过哪些没写进对话的判断？

## 3. 盲点分两种：反驳治逻辑，喂料治感知

想让"你见到的就是 AI 见到的"，光靠讨论不够：

- **逻辑盲点**（想法漏洞、误以为通用的特例）→ 让 AI 使劲反驳你；
- **感知盲点**（实机效果、设计稿、原理图、波形）→ AI 天生看不见，只能**喂同一份素材**：贴截图、给数据手册原文、做叠图比对。

我的 UI 开发 Skill 里"对图回修"之所以有效，就是因为它走的是感知闭环，而不是讨论闭环。

## 4. 必须有回路，且回路分强弱

AI 生成的内容必须被监督验证，这是整个工作流成立的前提。回路从弱到强：

**人肉抽查 < AI 看图比对 < 确定性脚本 < 实机运行**

两个推论：其一，**编译通过是嵌入式里最弱的门禁**，能编译和能跑是两回事，回路终点必须落到实机行为；其二，回路要足够便宜才跑得勤——把检查做成脚本，把"人肉看一眼修一轮"升级成"本地秒级修一轮"。

## 5. 别急着上多 Skill 的 Agent

Agent 解决的是**调度问题**（意图 → 路由给哪个 Skill），不是**执行精度问题**。只有一个工作流的时候套 Agent，纯属加中间层。正确节奏是：先把单个 Skill 打磨成确定性流水线，等 Skill 攒到四五个、自己都记不清该调哪个的时候，再写一个薄的编排 Agent（照课程那个"理解意图 → 门禁收集芯片型号和 demo 路径 → 路由"的样子），那时候它是水到渠成的一层。

## 6. 最小案例留成黄金范例，坑要回写

- **先生成最小可运行案例，再开枝散叶**——每一步都从上一个可运行状态出发，别一口气生成完再验证。
- 最小案例跑通后**保存成模板**（黄金范例），后面所有同类需求照抄骨架起步。
- **每次返工必须回写一条坑记录**（症状 / 原因 / 办法）再收工。蒸馏只是 Skill 的出生，坑回写才是它的成长——迭代二十次之后，这个 Skill 对你就是无可替代的资产。

# 结语：方法论全链路

> **框架立边界 → Skill 沉淀经验（蒸馏 / 逆向）→ 反驳 + 喂料补盲点 → 强回路验证 → 坑回写迭代 → Skill 攒够再上 Agent 编排**

这套链路里，课程教了前两步和最后一步的雏形，中间的盲点理论、回路强弱、坑回写，是我在自己项目的实战里补上的。AI 工具会过时（模型名、安装界面半年一换），但这套"怎么和 AI 协作"的方法论，是跟着项目走的长期资产。
