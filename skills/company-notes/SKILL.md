# 公司学习记录

把用户口述的公司相关内容归档进知识库 raw/公司学习/。**只归档不摄取**（摄取等用户明确说「摄取」）。只新增/追加，绝不修改或删除用户自己写入的文件。

## 分类

- `AI学习/` — AI 工作流、skill 方法论、AI+UI、知识库思考等
- `业务学习/` — 嵌入式开发、项目部署、芯片指令、调试经验等
- `职场学习/` — 做事方法、同事关系、沟通、汇报等

## 文件双轨制（雷点：别用错，2026-10-20 用户定的）

- **活文档**：会持续更新的主题（经验、方法、日常流程）。文件名**不带日期**；frontmatter 记 `date`（建档日）+ `updated`（最后更新）。更新时只改 `updated` 并在文末「## 更新记录」追加一行——**不改文件名、不新增文件**。正文保持精炼：新经验**合并进对应小节**而不是无限往下堆；一个文件里混出两个明显不同的主题、或正文长到两三屏难翻时，拆成子文件（参照 `手册存档/` 模式：独立文件 + 正文留链接）。
- **时点记录**：一次性的讨论整理、复盘。文件名带日期 `YYYY-MM-DD xxx.md`，封存不改。

## 文件格式

frontmatter（source: 用户口述 / 用户与AI讨论）+ AI 整理段（摄取时的导读）+ 原话摘录（一字不改，含语气词和错别字）+ 更新记录（活文档）。

## 雷点（2026-10-20 踩过的，别再踩）

1. **长文原文不内嵌正文**：手册、指令集等大段材料放独立子文件夹（如 `业务学习/手册存档/`），正文里只留 markdown 相对链接 + 一句话简介——用户明确嫌内嵌长文"慢慢拉下去很难看"。
2. **台账同步**：`raw/公司学习/待摄取.md` 随文件变动更新（新增、改名、移动路径都要改）。
3. **讨论不等于口述**：用户说"讨论一下/不用写进raw"的内容不归档；讨论后用户确认的结论，问一句是否沉淀，确认后追加进对应活文档或建讨论整理页（时点记录）。
4. **不写死盘符绝对路径**：一切路径相对仓库根（如 `raw/公司学习/`）。用户双机使用——公司机 `<公司机大脑仓库路径>`，家用机 `<家用机大脑仓库路径>`——写死哪个都坑另一台。
5. **隐私边界**：公司内容默认随仓库推 GitHub 私有仓库；日记类已 gitignore 隔离；用户提到新的敏感内容时，提醒确认是否入库或加 .gitignore。
6. **git 杂症**：push 偶发 `HTTP/2 stream` 错误→重试一次即可；status 里大量「已修改」是 CRLF/LF 幻影差异，不是真改动，不必处理。

## 收尾

按 AGENTS.md 的 Git 自动提交规则提交推送，提交信息格式：`新增公司学习 <分类> <简述>` / `追加<文件名> <简述>`。
