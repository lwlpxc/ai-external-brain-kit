# 每日日记记录

把用户口述的当天内容按框架整理进知识库。**只归档不摄取**（摄取按月、跨月后进行）。

## 执行步骤

1. **确认日期**：用系统当前日期（YYYY-MM-DD）。
2. **写入或追加** 仓库根下 `raw/日记/<YYYY-MM-DD>.md`（以当前机器的仓库实际路径为根，不写死盘符）：
   - 文件不存在 → 新建，结构如下；
   - 文件已存在 → 在文末追加一个 `## 补记 HH:MM` 段（同格式），不改动已有内容。

```markdown
---
source: 用户日记
type: diary
date: YYYY-MM-DD
recorded: YYYY-MM-DD
---

# YYYY-MM-DD 日记

## 今日记录（AI 整理段，摄取时以此为导读，不作原话引用）

> 框架是菜单不是清单：只写用户实际聊到的板块，没聊到的整段省略，不凑数、不诱导。

- **公司/工作**：今天在公司学到、观察到、踩到的（技术或职场）
- **职业规划与生意思考**：对以后方向、做生意、提升个人价值的想法
- **今日感悟**：不归属以上板块的个人感想
- **读书笔记**：书名 + 要点（大段深入的书评可建议用户走 course-notes 式单独归档）
- **面试记录**：公司/岗位/被问问题/自己答得如何/复盘

## 原话摘录（一字不改）

<用户口述原文原样放入>
```

3. **纪律**：
   - 「原话摘录」段一字不改，包括语气词和负面情绪表达——那是日记最有价值的部分
   - 板块菜单只填聊到的；用户提到"以后要做 X/明天打算 X"这类**计划**时，整理进对应板块，但顺口提醒一句"计划可以同步记到 Notion 待办"（用户自定：计划管在 Notion，日记只管记录）
   - 只新增/追加当天文件，不碰其他任何 raw/ 文件
   - 不更新 wiki/log.md（摄取阶段才动）
   - **隐私**：`raw/日记/` 已加入 .gitignore，不进 git/GitHub。相关 git 操作只针对其他文件
4. **维护台账** 仓库根下 `raw/日记/待摄取.md`：按月记录待摄取篇数，格式 `- 2026-10：N 篇（01、02、…）`。每次记录后更新。（台账本身不含日记内容，可进 git）
5. **摄取触发器**（两条都要执行）：
   - **月初提醒**：每月 1~5 日期间若用户来对话，主动问一句"上个月日记（N 篇）要不要摄取进 wiki？"
   - **软提醒**：当月待摄取累积到 8 篇以上时，顺口提一句攒了不少。
   - **摄取规则**：用户同意后才摄取，且**只摄取已结束的月份**——当月（未过完）的内容一律不摄取。摄取时并入 `wiki/摘要/日记/日记-YYYY-MM.md` 月度页（无则新建，有则追加）：除内容聚合外，**必须把当月原话中最有代表性的句子（原话摘录段里的）直接引用进步度页**，保留用户自己的措辞；如出现新的重复主题可更新 `日记-主题提炼` 页；完成后清空台账对应条目、更新 wiki/index.md 与 log.md。
6. **收尾**：按 AGENTS.md 的 Git 自动提交规则提交推送，提交信息：`记日记 YYYY-MM-DD → raw/日记/`。
